# 認証は DB 保存の不透明セッショントークンとする

- **決定**: ログイン時にランダムなセッショントークンを発行し、ハッシュを DB に保存する（有効期限つき）。web は httpOnly クッキーで保持して API へ Bearer として転送し、モバイルは Bearer で直接送る。パスワードは argon2id、メール確認・パスワードリセットのトークンはハッシュ保存の使い切りで有効期限を付ける
- **文脈**: web とモバイルの両方から使える認証が要る。ログアウトで以降ゲスト扱いになること、パスワードリセット後に古い認証が残らないことが要件
- **検討した案**:
  - 案A: 不透明セッショントークン（DB 保存）
  - 案B: 短寿命 JWT + リフレッシュトークン
- **採用理由**: ログアウトとパスワード変更後の失効が即時に効く。実装が単純で、この規模（ピーク毎分500件）なら毎回の DB 参照は問題にならない
- **トレードオフ**: 毎リクエストでセッションの参照が要り、規模が大きく伸びたときは参照の負荷が増える（キャッシュで緩和できる）。JWT は DB 参照を省けるが、失効の即時性に欠けリフレッシュの実装が増えるため退けた
- **影響範囲**: `apps/api` の認証ミドルウェア、`sessions` テーブル、`apps/web` のクッキー処理
