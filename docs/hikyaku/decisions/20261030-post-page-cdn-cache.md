# 単体ページのアクセス集中は CloudFront の短 TTL キャッシュで受ける

- **決定**: CloudFront を前段に置き、ゲストの公開投稿の取得だけを短い TTL（10秒程度）でキャッシュする。ログインユーザーと非公開の投稿はキャッシュしない。`is_liked_by_me` などの個人別の状態は別リクエストで取得する。投稿の削除と公開範囲の変更時は該当 URL を無効化する
- **文脈**: 単体ページに毎分5,000件が30分続いても、単体ページを表示し続け、ほかの機能も止めない。常時のコストは最小限に抑える
- **検討した案**:
  - 案A: CloudFront で短 TTL キャッシュ + 無効化
  - 案B: キャッシュなしで ECS のオートスケールだけで耐える
- **採用理由**: 集中時も DB と API に届くリクエストが大幅に減り、常時の余剰タスクが要らない
- **無効化の方式**: 削除は該当 URL を、非公開化は `/posts/*` をワイルドカードで無効化する。失敗時は再試行し、その間も TTL で古い表示が消える。ゲストに最大 10 秒の古い表示が残ることは、US-5.2 / 11.3 の即時反映に対する既知の逸脱として受け入れる
- **トレードオフ**: 無効化が間に合わない場合、削除や非公開化の後も最大 TTL 分（数秒）はゲストにキャッシュが見える。個人別の状態を分離するため、画面の構成が複雑になる。オートスケールのみの案は、毎分5,000件（約83 rps）の主キー参照なら DB は耐えられるが、スケールの遅れで他機能に影響しうるため退けた
- **影響範囲**: `apps/api` の投稿取得 API のキャッシュヘッダ、`apps/web` の単体ページ、CloudFront の設定（`infra/`）
