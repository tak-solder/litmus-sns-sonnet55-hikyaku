# 検索は PostgreSQL + pg_bigm で行う

- **決定**: 投稿本文を NFKC 正規化して小文字化した検索用列を持ち、pg_bigm（2-gram の GIN 索引）で `LIKE` 検索する。AND / OR / 除外 / フレーズは検索クエリのパーサーで解釈し、SQL の条件に変換する
- **文脈**: 日本語の部分一致を、投稿500万件で 3 秒（p95）以内に返す必要がある。英字の大文字小文字と全角半角は同一視し、ひらがなとカタカナは同一視しない。追加の AWS サービスは費用の目安（月300米ドル）に収めたい
- **検討した案**:
  - 案A: PostgreSQL + pg_bigm
  - 案B: PostgreSQL + pg_trgm
  - 案C: OpenSearch
- **採用理由**: 追加サービスが無く費用と運用が最小で、日本語でも1文字から索引が効く
- **トレードオフ**: RDS PostgreSQL が pg_bigm に対応している必要があり、構築時に確認が要る（非対応なら再検討する）。検索用列の分だけ容量が増える。pg_trgm は日本語で DB のロケール次第で索引が効かず、短い語が全件走査になるため退けた。OpenSearch は検索性能が高いが、費用・運用が重く、投稿との同期も要るため退けた
- **影響範囲**: `posts` テーブルと索引、検索クエリのパーサー（`packages/*`）、RDS の拡張設定
