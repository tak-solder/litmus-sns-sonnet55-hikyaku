# ドキュメントガイド

このリポジトリの永続ドキュメントが、どこに、誰の管理で存在するかを宣言します。
Hikyaku はこのファイルを唯一の手がかりとして永続ドキュメントを読み書きします。

| 管理 | 意味 |
| --- | --- |
| `hikyaku` | Hikyaku のテンプレートに従う。形式まで Hikyaku が決める |
| `repo` | 既存形式が正。Hikyaku は追記のみで、形式には手を出さない |
| `未作成` | まだ無い。次に必要になったとき Hikyaku が作成する |
| `対象外` | 意図的に持たない。理由を概要欄に書く |

| 論理名         | 管理   | パス | 概要                                                                          |
| -------------- | ------ | ---- | ----------------------------------------------------------------------------- |
| overview       | 未作成 | —    | システムの責務・境界・データフローと、正がどこにあるかのポインタ              |
| decisions      | 未作成 | —    | 設計判断（ADR）。コードから復元できない唯一の情報                             |
| constraints    | 未作成 | —    | 性能・可用性・セキュリティ・互換性などの制約                                  |
| learnings      | 未作成 | —    | 再現条件が明確な落とし穴と回避策                                              |
| conventions    | 未作成 | —    | コーディング規約。AI が自動で読む AGENTS.md が既定のマップ先                  |
| glossary       | 未作成 | —    | （任意）ドメイン用語集。人間が権威を持って定義したものだけが価値を持つ        |
| test-strategy  | 未作成 | —    | （任意）テスト方針。conventions に含めても成立する                            |
| security-model | 未作成 | —    | （任意）認証認可方式・信頼境界。原則は constraints に統合し、肥大化時のみ分離 |
| tech-stack     | 未作成 | —    | （任意）参考。正は lockfile / マニフェスト                                    |
| db-schema      | 未作成 | —    | （任意）参考。正はマイグレーション                                            |
| interfaces     | 未作成 | —    | （任意）参考。正は OpenAPI / 型定義                                           |
