# ユーザーストーリー

## 概要

### 実現したいこと

イラスト・写真・ハンドメイドなどを趣味で創作する人が、作品と制作の近況を気軽に発信し、ファンや創作仲間とつながるための短文 SNS を、MVP として作る。

- 作品は画像1枚と短いテキスト（300文字以内）で手軽に投稿できる。
- フォローしたクリエイターの新作はタイムラインで追える。
- キーワード検索（部分一致、AND / OR / 除外 / フレーズ）で、関心のある作品に出会える。
- 制作途中の作品や私的な近況は、承認したフォロワーだけが見られる「非公開」にできる。
- 話題が雑多に流れる汎用 SNS とは違い、作品と制作を軸にした交流に絞った場にする。

### 背景・目的

想定するユーザーは、日本国内で趣味の創作をしている個人（10〜40代が中心）と、その作品のファンや創作仲間である。
発信する側の多くはフォロワーが数十〜数百人の規模だが、一部の人気クリエイターは数万人にフォローされる。
見る側の多くはスマートフォンから閲覧し、ログインせずに作品を眺めてから登録することも多い。

汎用 SNS では、作品の投稿が雑多な話題に埋もれて、届けたい相手に届きにくい。
また公開範囲が全体公開しか無いと、制作途中の作品や私的な近況を見せる相手を選べない。
このサービスは、作品と制作に絞った場を小さく立ち上げ、利用者の反応を見ながら機能を広げていくことを目的とする。

### 対象画面・対象データ

- 画面: トップページ、ユーザー登録、ログイン、メールアドレス確認、パスワードリセット、グローバルフィード、タイムライン、投稿検索、投稿作成、投稿単体ページ、ユーザーページ、公開範囲の設定、フォロー申請一覧、フォロワー一覧
- データ: ユーザー（名前・メールアドレス・パスワード・公開範囲）、投稿（本文・画像）、フォロー関係（申請中を含む）、いいね、メールアドレス確認・パスワードリセット用のトークン

### 制約・要件

機能の共通仕様:

- グローバルフィード・タイムライン・検索・ユーザーページの投稿一覧は、新しい順に1回最大20件を返し、続き（より古い投稿）も取得できる。
- フォロー申請一覧とフォロワー一覧も、新しい順（申請やフォローの日時の新しい順）に1回最大20件を返し、続きも取得できる。
- これらの一覧は、下までスクロールすると続きを自動で読み込む無限スクロールにする。
- 投稿は本文（300文字以内）と画像（最大1枚）からなり、どちらか一方があれば投稿できる。画像は JPEG / PNG / GIF / WebP で、1枚5MB以内。
- 公開範囲は投稿ごとではなくユーザーごとの設定で、設定を変えると過去の投稿にも即時に反映される。
- 「非公開」のユーザーの投稿を見られるのは、本人と、そのユーザーのフォロワーだけ。
- 非公開のユーザーをフォローするには申請が必要で、本人が承認して初めてフォロワーになる。
- 公開から非公開にしても既存のフォロワーはそのまま残り、非公開から公開にすると未処理のフォロー申請は破棄される。

技術スタック:

- 言語は TypeScript。Web UI と BFF は Next.js（`apps/web`）、API サーバーは Hono（`apps/api`）。それ以外のライブラリは自由に選んでよい。
- リポジトリには `apps/web` と `apps/api` の初期構築と、それらを起動する `docker compose` の設定が用意されている。ここから実装を始める。
- 将来のモバイルアプリ開発を検討しているため、バックエンドはモバイルアプリからも利用できる API として実装する。API の方式・エンドポイント・データ形式・Web UI との処理の共有のしかたは設計フェーズで決める。

非機能要件（設計フェーズへの引き継ぎ。インターネットに公開する本番サービスの水準を満たすこと）:

- 運用開始時点の規模: 登録ユーザー 1,000人（日次利用者 100〜300人）、ピーク時のリクエストは読み取り 毎分50件・書き込み 毎分5件。
- 1年後の規模: 登録ユーザー 10万人（日次利用者 1万人）、投稿 累計500万件（1日約1.5万件）、いいね 累計5,000万件、フォロー関係 累計500万件。
  - 1人がフォローできるのは最大5,000人。フォロワー数に上限は無く、5万人以上にフォローされるユーザーもいる。
  - ピーク時のリクエストは読み取り 毎分500件・書き込み 毎分50件。
- 1年後の規模とピーク負荷のもとでの応答時間（95パーセンタイル）:
  - 投稿一覧（グローバルフィード・タイムライン・ユーザーページ）と単体ページ: 1秒以内
  - 投稿の検索: 3秒以内
  - 書き込み（画像のアップロードを除く）: 1秒以内
- 規模が数倍になっても、作り直さずにサーバーの増強や台数の追加で対応できる設計にする。一方で運用開始時点の規模に見合う構成で始め、AWS の費用は月額300米ドル以内を目安とし、段階的に増強できる構成が望ましい。
- 単体ページへのアクセス集中（目安: 毎分5,000件が単体ページだけに30分続く）でも、単体ページを表示し続け、ほかの機能も止まらないこと。常時のコストは最小限に抑える。
- 月間稼働率 99.9% を運用開始時点から目標とする。
- 本番環境は AWS 東京リージョン（ap-northeast-1）。実行環境は ECS、データベースは PostgreSQL を必ず使う。それ以外の AWS サービスは必要に応じて追加してよい。
- Web UI は日本語で、最新版の Chrome / Safari / Firefox / Edge の PC とスマートフォンの画面幅の両方で使えること。日時は日本時間で表示する。
- リポジトリは、複数人の開発チームが継続的に開発し、本番リリースを繰り返す前提で整える。
- ローカルでは `docker compose up` の1コマンドで、データベースなど依存するものを含めてすべてが起動すること。ローカルで送信したメールは実際には送らず、メールキャッチャーに届くこと。

MVP 完了時の成果物:

- ソースコード一式
- README（起動手順、Web UI と API の URL）
- API の仕様書（操作の一覧、リクエストとレスポンスの形式、エラーの返し方。OpenAPI や GraphQL スキーマなど方式に合った形式）
- 本番環境のインフラのコード（Terraform、AWS CDK など。本番構成に必要な AWS リソースをすべてコードで構築できること）

## スコープ外

- モバイルアプリの開発 — 将来の検討事項。このサイクルでは API をモバイルアプリからも使える形にするところまで
- 投稿の編集 — 要件から外した（投稿は作成と削除のみ）
- 動画、複数枚の画像 — 要件から外した（画像は1枚に限定）
- 投稿ごとの公開範囲設定 — 要件から外した（公開範囲はユーザー単位の設定とする）
- 自分の投稿へのいいね、自分自身のフォロー — 要件から外した
- フォロー中一覧の表示、他ユーザーのフォロワー一覧の表示 — 要件から外した（フォロワー一覧は自分のものだけを、フォロワーを外すために持つ）
- プロフィール編集（名前・メールアドレス・パスワードの変更）、退会 — 要件から外した
- 返信・リポスト・通知 — 要件から外した
- ユーザー名での検索、投稿者や期間での検索の絞り込み — 要件から外した（検索は投稿本文のキーワード検索のみ）
- ひらがなとカタカナの同一視、表記ゆれ・同義語の吸収 — 要件から外した（検索の文字の同一視は英字の大文字小文字と全角半角までとする）

## US-1: ユーザー登録とメールアドレス確認

**ユーザー**: ゲスト
**目的**: SNS に投稿・フォロー・いいねをするため
**操作**: 名前・メールアドレス・パスワードを入力して登録し、届いたメールでメールアドレスを確認する
**優先度**: Must
**受け入れ基準**:
- [ ] US-1.1: 名前・メールアドレス・パスワードを入力して登録できる
- [ ] US-1.2: 既に登録済みのメールアドレスでは、新しいアカウントは作成されない
- [ ] US-1.3: 名前・メールアドレス・パスワードのいずれかが未入力、またはメールアドレスの形式が不正な場合は登録できず、理由が表示される
- [ ] US-1.4: 登録すると、入力したメールアドレス宛に確認用のメールが届く
- [ ] US-1.5: 確認メールのリンクを開くとメールアドレスの確認が完了し、ログインできるようになる
- [ ] US-1.6: 確認が完了するまでは、正しいメールアドレスとパスワードでもログインできず、確認が必要である旨が表示される
- [ ] US-1.7: 登録直後の公開範囲は「公開」になる
- [ ] US-1.8: 確認が完了していないユーザーは、確認メールを再送できる

## US-2: ログインとログアウト

**ユーザー**: 登録済みユーザー
**目的**: 自分として投稿・フォロー・いいねをするため
**操作**: メールアドレスとパスワードでログインし、使い終わったらログアウトする
**優先度**: Must
**受け入れ基準**:
- [ ] US-2.1: メールアドレス確認済みのユーザーは、正しいメールアドレスとパスワードでログインできる
- [ ] US-2.2: メールアドレスまたはパスワードが誤っている場合はログインできず、エラーが表示される
- [ ] US-2.3: ログアウトすると、以降はゲストとして扱われる

## US-3: パスワードリセット

**ユーザー**: パスワードを忘れた登録済みユーザー
**目的**: 再びログインできるようにするため
**操作**: メールアドレスを入力してリセット用のメールを受け取り、新しいパスワードを設定する
**優先度**: Must
**受け入れ基準**:
- [ ] US-3.1: 登録済みのメールアドレスを入力すると、そのアドレス宛にリセット用のメールが届く
- [ ] US-3.2: リセット用のリンクから新しいパスワードを設定すると、新しいパスワードでログインでき、古いパスワードではログインできなくなる

## US-4: 投稿の作成

**ユーザー**: ログインユーザー
**目的**: 自分の発言や写真を他のユーザーに届けるため
**操作**: テキストを入力し、必要なら画像を1枚添えて投稿する
**優先度**: Must
**受け入れ基準**:
- [ ] US-4.1: 300文字以内のテキストだけで投稿できる
- [ ] US-4.2: 本文も画像も無い場合（空白や改行だけの本文は、本文が無いものとみなす）、または本文が301文字以上の場合は投稿できず、理由が表示される
- [ ] US-4.3: 投稿した内容が、自分のタイムラインとグローバルフィードの先頭に表示される。グローバルフィードでほかの閲覧者に表示されるかは、公開範囲に従う
- [ ] US-4.4: ゲストは投稿できない
- [ ] US-4.5: 画像を1枚添えて投稿でき、本文は空でもよい
- [ ] US-4.6: 2枚以上の画像、JPEG / PNG / GIF / WebP 以外の形式、5MB を超える画像は添付できず、理由が表示される
- [ ] US-4.7: 画像付きの投稿は、表示されるすべての場所（各一覧と単体ページ）で画像も表示される

## US-5: 投稿の削除

**ユーザー**: ログインユーザー
**目的**: 不要になった自分の投稿を取り下げるため
**操作**: 自分の投稿を削除する
**優先度**: Must
**受け入れ基準**:
- [ ] US-5.1: 自分の投稿を削除できる
- [ ] US-5.2: 削除した投稿は、グローバルフィード・タイムライン・検索結果・ユーザーページ・単体ページのいずれにも表示されなくなる

## US-6: フォローとフォロー解除

**ユーザー**: ログインユーザー
**目的**: 関心のあるユーザーの投稿をタイムラインで追うため
**操作**: 投稿者名からユーザーページを開き、フォロー／フォロー解除する
**優先度**: Must
**受け入れ基準**:
- [ ] US-6.1: 投稿者名からそのユーザーのユーザーページに移動できる
- [ ] US-6.2: ユーザーページには、そのユーザーの名前と、閲覧者が見られる投稿の一覧が新しい順に表示される（取得件数・続きの取得・含める項目はフィードと同じ）
- [ ] US-6.3: 他ユーザーのユーザーページでフォローでき、フォロー済みであることが分かる
- [ ] US-6.4: フォロー済みのユーザーのフォローを解除できる
- [ ] US-6.5: 自分自身はフォローできない
- [ ] US-6.6: ゲストはユーザーページを閲覧できるが、フォローはできない
- [ ] US-6.7: 「非公開」のユーザーに対しては、フォローではなくフォロー申請になり、申請中であることが分かる。本人が承認するまでフォロワーにはならない
- [ ] US-6.8: 申請中のフォロー申請は、申請した側が取り消せる
- [ ] US-6.9: 「非公開」のユーザーのユーザーページでは、投稿を見る権限が無い閲覧者にも名前とフォロー（申請）ボタンは表示され、投稿が非公開であることが分かる
- [ ] US-6.10: フォロー中と申請中の合計が5,000人に達すると、それ以上フォローもフォロー申請もできず、その旨が表示される

## US-7: いいねといいねの取り消し

**ユーザー**: ログインユーザー
**目的**: 他ユーザーの投稿への共感を伝えるため
**操作**: 他ユーザーの投稿にいいねする／いいねを取り消す
**優先度**: Must
**受け入れ基準**:
- [ ] US-7.1: 他ユーザーの投稿にいいねでき、合計いいね数が1増え、自分がいいね済みであることが分かる
- [ ] US-7.2: いいね済みの投稿のいいねを取り消すと、合計いいね数が1減り、いいね済みでなくなる
- [ ] US-7.3: 同じ投稿に重複していいねすることはできない（合計いいね数は1人につき最大1）
- [ ] US-7.4: 自分の投稿にはいいねできない
- [ ] US-7.5: ゲストはいいねできない

## US-8: グローバルフィードの閲覧

**ユーザー**: ゲストおよびログインユーザー
**目的**: システム全体の最新の投稿を知るため
**操作**: グローバルフィードを開く
**優先度**: Must
**受け入れ基準**:
- [ ] US-8.1: 閲覧者が見られる投稿が新しい順に、1回最大20件表示される
- [ ] US-8.2: 続き（より古い投稿）を最大20件ずつ取得できる
- [ ] US-8.3: 各投稿に、本文・画像・投稿日時・投稿者名・合計いいね数・自分がいいね済みか（is_liked_by_me）が含まれる
- [ ] US-8.4: ゲストが閲覧した場合、is_liked_by_me はすべて false になる
- [ ] US-8.5: 「非公開」のユーザーの投稿は、本人とそのフォロワーにだけ表示され、ゲストには表示されない

## US-9: タイムラインの閲覧

**ユーザー**: ログインユーザー
**目的**: フォローしているユーザーと自分の投稿をまとめて追うため
**操作**: タイムラインを開く
**優先度**: Must
**受け入れ基準**:
- [ ] US-9.1: 自分がフォローしているユーザーの投稿と自分自身の投稿のうち、自分が見られるものが新しい順に1回最大20件表示される
- [ ] US-9.2: フォローしていないユーザーの投稿は表示されない
- [ ] US-9.3: 続き（より古い投稿）を最大20件ずつ取得できる
- [ ] US-9.4: 各投稿に、本文・画像・投稿日時・投稿者名・合計いいね数・is_liked_by_me が含まれる
- [ ] US-9.5: 誰もフォローしていない場合は、自分の投稿だけが表示される
- [ ] US-9.6: ゲストはタイムラインを閲覧できず、ログインを求められる
- [ ] US-9.7: 「非公開」のユーザーにフォロー申請中の間は、その相手の投稿は表示されない。承認されると表示されるようになる

## US-10: 投稿の検索

**ユーザー**: ゲストおよびログインユーザー
**目的**: 特定の話題についての投稿を探すため
**操作**: キーワードを入力して投稿を検索する
**優先度**: Must
**受け入れ基準**:
- [ ] US-10.1: 本文にキーワードを含み、閲覧者が見られる投稿が、新しい順に1回最大20件表示される
- [ ] US-10.2: キーワードは部分一致で、英字の大文字・小文字と、英数字・カタカナの全角・半角は区別しない（例:「ＡＢＣ」で「abc」、「ｶﾀｶﾅ」で「カタカナ」がヒットする）
- [ ] US-10.3: 続き（より古い投稿）を最大20件ずつ取得できる
- [ ] US-10.4: 各投稿に、本文・画像・投稿日時・投稿者名・合計いいね数・is_liked_by_me が含まれ、ゲストの is_liked_by_me はすべて false になる
- [ ] US-10.5: キーワードが空（空白のみを含む）の場合は検索せず、その旨が表示される
- [ ] US-10.6: 空白（全角空白を含む）で区切った複数のキーワードを入力すると、すべてのキーワードを含む投稿がヒットする（AND）
- [ ] US-10.7: キーワードの前に「-」を付けると、その語を含む投稿が結果から除かれる
- [ ] US-10.8: キーワードの間に「OR」を置くと、どちらかの語を含む投稿がヒットする
- [ ] US-10.9: 「"」で囲んだ語句は、空白を含めてその並びのとおりに含む投稿だけがヒットする
- [ ] US-10.10: 除外の語だけを入力した場合など、条件として成り立たない入力では検索せず、その旨が表示される

## US-11: 公開範囲の設定

**ユーザー**: ログインユーザー
**目的**: 自分の投稿を見せる相手を限定するため
**操作**: 自分の公開範囲を「公開」または「非公開」に切り替える
**優先度**: Must
**受け入れ基準**:
- [ ] US-11.1: 自分の公開範囲を「公開」と「非公開」のどちらかに切り替えられ、現在の設定が分かる
- [ ] US-11.2: 「非公開」の間、自分の投稿は自分とフォロワーにだけ表示され、ゲストを含むそれ以外の閲覧者には表示されない
- [ ] US-11.3: 設定の変更は、過去の投稿を含むすべての投稿に即時に反映される
- [ ] US-11.4: 「公開」から「非公開」に切り替えても、その時点のフォロワーはフォロワーのまま残り、投稿を見られる
- [ ] US-11.5: 「非公開」から「公開」に切り替えると、未処理のフォロー申請はすべて破棄される。申請していたユーザーは改めてフォローすればフォロワーになれる
- [ ] US-11.6: フォロワーがフォローを解除したり、本人に外されたりすると、そのユーザーからは「非公開」の投稿が見えなくなる

## US-12: 投稿の単体ページとシェア

**ユーザー**: ゲストおよびログインユーザー
**目的**: 特定の投稿を開いたり、サービスの外にシェアしたりするため
**操作**: 一覧の投稿から単体ページを開く、投稿をシェアする、またはシェアされた URL に直接アクセスする
**優先度**: Must
**受け入れ基準**:
- [ ] US-12.1: 各一覧の投稿から、その投稿の単体ページに移動できる
- [ ] US-12.2: 単体ページには、本文・画像・投稿日時・投稿者名・合計いいね数・is_liked_by_me が表示され、ゲストの is_liked_by_me は false になる
- [ ] US-12.3: 単体ページからいいね／いいねの取り消しと、投稿者のユーザーページへの移動ができる。自分の投稿なら削除もできる
- [ ] US-12.4: 各一覧と単体ページから投稿をシェアでき、シェアするとその投稿の単体ページの URL が発行される（URL のコピー、または端末の共有機能で他のアプリに渡せる）
- [ ] US-12.5: シェアされた URL を開くと、その投稿の単体ページが表示される

## US-13: フォロー申請の承認と拒否

**ユーザー**: 「非公開」のログインユーザー
**目的**: 投稿を見せる相手を自分で選ぶため
**操作**: 届いたフォロー申請の一覧を見て、承認または拒否する
**優先度**: Must
**受け入れ基準**:
- [ ] US-13.1: 自分宛ての未処理のフォロー申請を、申請者の名前つきで一覧できる
- [ ] US-13.2: 申請を承認すると、申請者は自分のフォロワーになり、自分の投稿を見られるようになる
- [ ] US-13.3: 申請を拒否すると申請は消え、申請者はフォロワーにならない。申請者は改めて申請できる

## US-14: フォロワーを外す

**ユーザー**: ログインユーザー
**目的**: 投稿を見せたくなくなった相手をフォロワーから外すため
**操作**: 自分のフォロワー一覧から、特定のフォロワーを外す
**優先度**: Must
**受け入れ基準**:
- [ ] US-14.1: 自分のフォロワーを名前つきで一覧できる
- [ ] US-14.2: フォロワー一覧から特定のフォロワーを外せる。外されたユーザーは自分をフォローしていない状態になる
- [ ] US-14.3: 外されたユーザーは、自分が「非公開」なら改めて申請でき、「公開」なら改めてフォローできる

## US-15: トップページ

**ユーザー**: ゲストおよびログインユーザー
**目的**: サイトを開いてすぐ、自分に合った投稿一覧を見るため
**操作**: トップページ（サイトのルート URL）を開く
**優先度**: Must
**受け入れ基準**:
- [ ] US-15.1: ゲストがトップページを開くと、グローバルフィードが表示され、ユーザー登録とログインへの導線がある
- [ ] US-15.2: ログインユーザーがトップページを開くと、タイムラインが表示される
- [ ] US-15.3: ログインユーザーは、トップページからグローバルフィードにタブで切り替えられ、タイムラインにも戻れる
