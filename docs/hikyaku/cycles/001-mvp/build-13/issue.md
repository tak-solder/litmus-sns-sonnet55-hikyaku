# Build 13: タイムラインAPI

## やること

- `GET /timeline` を実装する。フォロー中（`accepted`）のユーザーと自分の投稿のうち、自分が見られるものを新しい順に1回最大20件、`cursor` で続きを返す
- クエリは `posts(author_id, id desc)` の索引を使う。性能テストで不合格のときの代替（フォロー先ごとの上位20件を結合する形）に切り替えられるよう、クエリを1か所にまとめる
- ゲストは401。誰もフォローしていなければ自分の投稿だけを返す。申請中の相手の投稿は出さない（承認されると出る）

## やらないこと

- 性能テストそのもの（build-25）
- タイムラインの画面（build-17）

## 対応する受け入れ基準

- US-9.1, US-9.2, US-9.3, US-9.4, US-9.5, US-9.6, US-9.7, US-4.3, US-5.2

## 受け入れ基準

- [ ] フォロー中のユーザーと自分の投稿だけが新しい順に最大20件返り、続きを取得できる
- [ ] フォローしていないユーザー、申請中の相手の投稿は出ない。承認後に出る
- [ ] 誰もフォローしていないと自分の投稿だけが返る
- [ ] ゲストは401になる
- [ ] 自分の新しい投稿が先頭に出る。削除した投稿は出ない
